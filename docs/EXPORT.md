# 書き出しと対応範囲

## 出力と検証

書き出しは、単一ファイルのHEVC映像1トラック、AAC音声1トラック、および対応可能な単一サンプルの非ドロップフレームタイムコードを対象とします。
MP4の索引を使って境界付近へ移動し、IDRを含む圧縮データを調べて希望範囲を含む区間を選びます。
CRAやキーフレームフラグだけでは出力範囲を確定しません。
未対応の追加ストリームや時間構成は、黙って除外せずエラーにします。

映像と音声は圧縮済みパケットをコピーし、出力後にSHA-256、件数、パケットのPTS/DTSと長さを照合します。
先頭のIDRと表示開始位置を検査します。
通常の書き出しでは全フレームのデコードを行いません。
全フレームの検証は実素材テストで `VROMA_FULL_DECODE=1` を指定した場合だけ実行します。
タイムコードは再生成であり、原本のトラックとのバイト同一性は保証しません。
撮影日時は、実際に最初に表示される映像の原本内位置と時計補正から算出します。
AVFoundationの`creationDate`による読み戻しを確認してから保存を確定します。

```text
出力先/
  vroma_YYYYMMDD_HHMMSS.mp4
  vroma_01_YYYYMMDD_HHMMSS.mp4
  ExportManifest.json
  SourceMetadata/
    <原本SHA-256>/
      manifest.json
      0000-66747970.bin
      ...
```

`SourceMetadata`には原本の全トップレベルboxを未加工で保存し、`mdat`だけはヘッダーを保存します。
原本全体のSHA-256と各領域の位置、長さ、SHA-256を記録し、既存データも照合してから再利用します。
原本全体のハッシュは同じ編集画面内で保持し、ファイルの識別情報・サイズ・更新日時・変更日時が一致する場合に再利用します。
アプリを開き直した後や原本の変更後は全体を読み直します。
退避した追加データ自体は再利用のたびに照合します。
これらは原本の復元やメーカーソフトでの再利用を保証するデータではありません。
原本を変更したり、自動削除したりする処理はありません。

`ExportManifest.json`は、各クリップの希望範囲、計画範囲、検証済み範囲、原本のSHA-256、退避先、日時、検証結果を記録します。分割録画では`sources`に関係する原本と各原本内の範囲を列挙します。
書き出し先と同じボリュームの一時領域で処理し、既存ファイルを上書きしない操作でMP4を確定します。
同時に同じ保存先へ書き出す場合はロックで競合を検出します。
処理中はウィンドウ上部に段階・進捗とキャンセルボタンを表示します。
キャンセル後も完了済みクリップは残り、未完了の一時MP4は削除します。

## 現在の対応範囲

同じフォルダの`VID_YYYYMMDD_HHMMSS_連番.mp4`は、日時部分が同じで番号が連続するものを1本の録画として表示します。
連番の桁数や開始番号は固定しません。欠番がある区間や別フォルダの素材はつなぎません。
録画を選ぶと、全ファイルを通したタイムラインで再生、マーク移動、範囲調整、書き出しを行えます。
点線は元ファイルの境界です。境界をまたぐ範囲も、映像と音声を再圧縮せず1つのMP4に書き出します。
コーデック設定、色・回転情報などが異なりコピーで結合できない場合は、エラーを表示します。
地図、サムネイル列、素材の再指定画面、GPXとマークの出力先へのコピーも未実装です。
ファイル参照はブックマーク、絶対パス、サイズ、更新日時で保持します。
移動をブックマークで追跡できない場合や素材が変更された場合はエラーにします。

メディアエンジンは現在アプリ内にリンクしています。
専用の補助プロセスへの分離、App Sandboxでの権限受け渡し、Universalアプリの配布構成は未実装です。
Final Cut ProとChrovaの実画面での連携確認も未実施です。
